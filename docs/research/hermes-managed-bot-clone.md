# Hermes Agent's Telegram managed-bot onboarding

Research checked 2026-10-01 against [Hermes source](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/telegram_managed_bot.py) and [Telegram's managed-bot specification](https://core.telegram.org/api/bots/managed-bots).

## What Hermes does

Hermes offers **Automatic (scan QR → confirm in Telegram → done)** alongside manual BotFather-token setup. Its client creates a short-lived pairing at `https://setup.hermes-agent.nousresearch.com/v1/telegram/pairings`, receives a Telegram deep link and QR payload, asks the user to confirm **Create Bot** in Telegram, polls the pairing with a bearer token, then receives the new bot's token, username, and owner user ID. The CLI saves that token as `TELEGRAM_BOT_TOKEN`; the dashboard also saves allowed user IDs and restarts its gateway. [CLI client](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/telegram_managed_bot.py#L1-L165), [setup wizard](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/gateway_setup_wizard.py#L256-L281), [dashboard backend](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/web_routers/messaging.py#L705-L804).

Telegram's underlying feature is **managed bots**: the human user owns the new bot, while a designated manager bot can obtain its token and manage it. The manager must have bot management enabled through BotFather. The human's Telegram client performs creation; a bot cannot call `bots.createBot` itself. [Telegram managed bots](https://core.telegram.org/api/bots/managed-bots). Hermes's onboarding service implementation is not in the inspected public repository; its internal use of Telegram's APIs is an **inference** from its public client and Telegram's documented flow. [Hermes client](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/telegram_managed_bot.py#L1-L18), [Telegram managed bots](https://core.telegram.org/api/bots/managed-bots).

## Direct path for this bot's `/clone`

Our user is already inside Telegram, so the QR and Hermes pairing service are unnecessary. Keep `/clone <token>` as the existing option. When `/clone` has no token, show an **inline URL button** such as `Create bot in Telegram`, pointing to `https://t.me/newbot/<our_main_bot_username>?name=<encoded suggested name>`. Telegram explicitly supports this managed-bot creation link, including an optional suggested username. An inline URL button can open an HTTP URL. [Telegram deep-link syntax](https://core.telegram.org/api/links#managed-bot-creation-request-links), [inline button `url`](https://core.telegram.org/bots/api#inlinekeyboardbutton), [current `/clone` handler](../../telegram/middleware/clone.ts).

1. Enable bot management for the **main bot** in the BotFather Mini App; verify `getMe.can_manage_bots === true` before exposing the button. A clone created by this link must name our main bot as manager. [Telegram managed bots](https://core.telegram.org/api/bots/managed-bots), [Bot API `User.can_manage_bots`](https://core.telegram.org/bots/api#user).
2. Have the main bot receive `Update.managed_bot` and read `managed_bot.user.id` (the human owner) and `managed_bot.bot.id` (the new bot). Then call the main bot's `getManagedBotToken` with the **new bot ID**. The user confirms name and username in Telegram; no token is copied into chat. [Bot API `Update`](https://core.telegram.org/bots/api#update), [`ManagedBotUpdated`](https://core.telegram.org/bots/api#managedbotupdated), [`getManagedBotToken`](https://core.telegram.org/bots/api#getmanagedbottoken), [Telegram link flow](https://core.telegram.org/api/links#managed-bot-creation-request-links).
3. Validate the returned token and connect through the existing `createBot` → `prisma.bot.upsert` → `setWH` path, recording `managed_bot.user.id` as owner. Handle repeat delivery and token changes idempotently by stable **bot ID**, and ensure the update belongs to a recent `/clone` request by that human. These are proposed integration safeguards, not behavior claimed of Hermes. [Current creation flow](../../telegram/middleware/clone.ts), [current Bot model](../../prisma/schema.prisma), [Telegram update meaning](https://core.telegram.org/bots/api#managedbotupdated).
4. Add `managed_bot` to the main bot's webhook and polling `allowed_updates`, and to the separately maintained production startup list. The installed `grammy@1.39.3` with `@grammyjs/types@3.23.0` has no managed-bot types or methods, and its `API_CONSTANTS.ALL_UPDATE_TYPES` does **not** include `managed_bot` (checked locally). Upgrade grammY to a version with Bot API 9.6 support before adding the handler; the registry currently lists `grammy@1.46.0` with `@grammyjs/types@5.0.0`, but support should be confirmed from its installed definitions during implementation. [Bot API 9.6 changelog](https://core.telegram.org/bots/api-changelog#april-3-2026), [current webhook setup](../../scripts/set-webhook.ts), [current polling setup](../../telegram/runner/polling.ts), [production update list](../../scripts/start-production.mjs).

The **inline button must be a URL button**. Telegram's special `KeyboardButton.request_managed_bot` opens a similar native creation flow, but that is a **reply keyboard button in a private chat**, not an inline button. The `managed_bot_created` service message is tied to that reply-keyboard request, so the inline-link path should use `Update.managed_bot` for completion. The link itself carries no arbitrary pairing ID and produces no callback query; correlate by the authenticated owner ID and a short-lived pending `/clone` record. [Bot API managed-bot keyboard](https://core.telegram.org/bots/api#keyboardbuttonrequestmanagedbot), [Telegram bot buttons](https://core.telegram.org/api/bots/buttons), [Telegram managed-bot updates](https://core.telegram.org/api/bots/managed-bots), [Telegram deep links](https://core.telegram.org/api/links#managed-bot-creation-request-links).

The manager can retrieve or replace managed-bot tokens. This gives the main bot a continuing credential-management role, so keep the retrieved token server-side, avoid placing it in callback data or logs, and handle future `managed_bot` updates for revocation/rotation. Telegram documents bot-create limits and username conflicts as possible user-facing creation failures. [Telegram managed bots](https://core.telegram.org/api/bots/managed-bots), [`getManagedBotToken`](https://core.telegram.org/bots/api#getmanagedbottoken), [`replaceManagedBotToken`](https://core.telegram.org/bots/api#replacemanagedbottoken).

**Verification boundary:** source and API behavior above are documented; no live managed-bot creation was performed, so client compatibility and our main bot's manager permission remain implementation-time checks. The current installed grammY version's missing update support was verified locally. [Telegram managed-bot specification](https://core.telegram.org/api/bots/managed-bots), [Hermes client](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/telegram_managed_bot.py).
